Simon Willison

Aug 19
A new pattern for extensible software: LLMs lower the cost of authoring safe user extensions, and sandboxing primitives make deployment frictionless.
TL;DR — PM TakeawayThis is a significant product architecture shift. Instead of building monolithic features, you can create a core system and let users extend it with LLM-generated code running in a lightweight sandbox. For PMs, this means a new lever for customization and user empowerment—without the traditional cost of supporting N+1 code paths. Consider this for your roadmap: which high-variance user needs could you serve by enabling LLM-powered extensions instead of building them yourself?
Read more

Simon quotes research showing that LLMs radically lower the cost of writing extensions, and modern sandbox primitives (like smolvm) make it safe to run untrusted code with resource limits. This opens a new product design pattern: a solid, accountable core with user-extensible behavior powered by AI.

For product teams, this shifts the economics of customization. Instead of maintaining custom implementations for each customer, you can expose extension points and let users (or support teams) generate extensions via LLM prompts. This scales personalization without scaling your engineering overhead.

If your system has clear rules and coherent design, AI can amplify that. If it's a mess, AI will make it messier faster.
Read more

Simon discusses "conceptual integrity"—the degree to which a system follows a coherent design philosophy—as a better metric than LOC. When AI agents can write 10,000 lines in a day, the limiting factor shifts from "can we write this?" to "do we understand what we're building?"

For PMs, this means your product architecture and design coherence become bottlenecks. If your system is well-designed and your APIs are clear, AI agents will extend it cleanly. If it's a hairball of accidental complexity, AI will add more hairballs. Start viewing architecture clarity as a PM responsibility, not just an engineering concern.
