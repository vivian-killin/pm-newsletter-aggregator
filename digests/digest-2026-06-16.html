How Braintrust uses AI agents, evals, and CI to ship better software
TL;DR — PM TakeawayTreat evaluations as PRDs for AI systems. Define measurable quality criteria upfront, automate the feedback loop, and use evals in CI to maintain taste and consistency as agents evolve. This shifts PM work from writing features to encoding values.
Read more

Ankur Goyal unpacks how Braintrust uses evals—automated test harnesses for AI behavior—as a modern replacement for traditional product requirements documents. Instead of describing what users want, you describe what good looks like: correct outputs, coherent reasoning, tone, safety constraints. Evals become the source of truth for agent quality.

The framework has three layers: first, define the taste you want encoded (accuracy, style, safety). Second, automate continuous evaluation so every change is tested. Third, treat evals as CI gates—no merge without proof the agent still performs well. This approach scales taste across teams and prevents regression as models are swapped or prompts are tuned.

Satya on Loopcraft: Building Frontier Ecosystems
TL;DR — PM TakeawayLoopcraft is a new design paradigm for frontier AI systems: building agentic loops that compound over time—humans define the loop, AI executes repeatedly, humans refine. This is how PMs should think about building AI products: not as one-shot tools, but as self-improving feedback systems that learn from repeated execution.
Read more

Swyx reports on Satya Nadella's essay on loopcraft: the art of building systems that leverage repeated AI execution and human feedback to compound value. The core idea is that frontier AI models are powerful at executing narrow, well-defined loops—if you define the loop clearly, AI can execute it at scale, and humans can then refine the loop based on results.

This reframes product strategy: instead of thinking "what can AI do for me once," think "what loops can AI execute repeatedly that humans can incrementally improve?" Apply this to customer support (refine the support loop with each ticket), code generation (refine the generation loop with each deployment), or content creation (refine the writing loop with each publication).

Worth your time regardless of when it was published
Why it's worth your timeThe "jailbreak" that triggered Fable's export restrictions was researchers asking the model to fix deliberately insecure code. This reframes a critical question for PMs: is restricting AI's ability to reason about security a feature or a liability? Understanding the policy mechanics helps you anticipate how government action reshapes the competitive landscape.
Read more

Willison investigates the White House's concern about Fable and finds that the trigger wasn't a sophisticated attack, but a straightforward cybersecurity task: patch this buggy code. Anthropic restricted Fable under export controls because the model performed too well at vulnerability analysis. This collides two forces: governments want AI-powered security tools, but they don't want adversaries using the same models. The result: a capability becomes a liability.

For PMs in frontier AI, this is a signal that government policy will increasingly shape product strategy. Features that seem obviously useful (AI debugger, security auditor, code analyzer) may trigger export controls or regulatory action. Building in public, anticipating policy friction, and diversifying your user base geographically becomes part of product risk.
